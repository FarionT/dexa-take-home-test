# Employees API

HR (role `ADMIN`) manages employees and their login accounts. Every employee has exactly one login, created and managed together with the employee: there is no separate user list.

| | |
|---|---|
| Base URL (dev) | `http://localhost:3000` |
| Auth | `Authorization: Bearer <access_token>` on every endpoint (see [Auth API](auth.md)) |
| Response body | Always `{ status, message, data? }`, see [Auth API → Response format](auth.md#response-format) |
| Field names | `snake_case` |

## Endpoints

| Method | Path | Access | Purpose |
|--------|------|--------|---------|
| `GET` | [`/departments`](#get-departments) | ADMIN | Department choices for the employee form |
| `GET` | [`/employees`](#get-employees) | ADMIN | List with search, filters and pagination |
| `GET` | [`/employees/me`](#get-employeesme) | any logged-in user | The caller's own employee profile |
| `GET` | [`/employees/:id`](#get-employeesid) | ADMIN | One employee, with their login |
| `POST` | [`/employees`](#post-employees) | ADMIN | Create an employee **and** their login; returns a temporary password once |
| `PATCH` | [`/employees/:id`](#patch-employeesid) | ADMIN | Update profile, status (deactivate / reactivate) and role |
| `POST` | [`/employees/:id/reset-password`](#post-employeesidreset-password) | ADMIN | Give the employee a new temporary password |
| `DELETE` | [`/employees/:id`](#delete-employeesid) | ADMIN | Soft-delete a record created **by mistake** (not for resignations) |

Any endpoint marked ADMIN returns `403 You do not have permission to do this.` for an `EMPLOYEE`. `:id` must be a UUID, otherwise `400 Validation failed (uuid is expected)`.

## Objects

### Employee object

```json
{
  "id": "d0c05509-fcfd-4041-a6bf-1a2121e13929",
  "employee_code": "EMP-0002",
  "full_name": "Budi Santoso",
  "email": "budi@dexa.local",
  "phone": "+62 812-3456-7890",
  "position": "Developer",
  "department": { "id": "d0000000-0000-4000-8000-000000000002", "name": "Engineering" },
  "hire_date": "2026-11-10",
  "status": "ACTIVE",
  "created_by": "e0000000-0000-4000-8000-000000000001",
  "updated_by": "e0000000-0000-4000-8000-000000000001",
  "created_at": "2026-11-06T09:12:30.000Z",
  "updated_at": "2026-11-06T09:12:30.000Z",
  "account": {
    "user_id": "6f9d3b1e-2c4a-4e8b-9a7f-1d2e3c4b5a69",
    "employee_id": "d0c05509-fcfd-4041-a6bf-1a2121e13929",
    "email": "budi@dexa.local",
    "role": "EMPLOYEE",
    "is_active": true,
    "must_change_password": true,
    "last_login_at": null
  }
}
```

| Field | Description |
|-------|-------------|
| `employee_code` | `EMP-0001`, `EMP-0002`, … generated by the system, never reused. As text, `EMP-10000` sorts before `EMP-9999`: sort by `created_at` |
| `phone` | `null` when not set |
| `department` | `{ id, name }`. Still shown if the department was deleted later |
| `hire_date` | `YYYY-MM-DD` |
| `status` | `ACTIVE` or `INACTIVE` (resigned / suspended). An `INACTIVE` employee can't log in |
| `created_by` / `updated_by` | Employee ids of the HR users who made the change; `null` for seeded rows |
| `created_at` / `updated_at` | ISO 8601, UTC |
| `account` | The login (see below). `null` only if the employee somehow has no login, so HR can spot and fix it |

### Account object

The login side of an employee. Never contains a password or hash.

| Field | Description |
|-------|-------------|
| `user_id` | Login id |
| `employee_id` | The employee it belongs to |
| `email` | Login email: always the same as the employee's `email` |
| `role` | `ADMIN` (HR) or `EMPLOYEE` |
| `is_active` | `false` when the employee is `INACTIVE` |
| `must_change_password` | `true` while the employee still has a temporary password |
| `last_login_at` | ISO 8601 or `null` (never logged in) |

### Department object

## `GET /employees`

**ADMIN.** Live employees (deleted ones are hidden), newest first.

### Query parameters

| Param | Default | Rules |
|-------|---------|-------|
| `page` | `1` | Whole number ≥ 1 |
| `limit` | `10` | Whole number 1–100 |
| `search` | — | Up to 100 characters. Partial, case-insensitive match on name, employee code or email (`%` and `_` are matched literally) |
| `department_id` | — | Department UUID |
| `status` | — | `ACTIVE` or `INACTIVE` |

```bash
curl -s "http://localhost:3000/employees?page=1&limit=10&search=budi&status=ACTIVE" -H "Authorization: Bearer $TOKEN"
```

### Response `200 OK`

```json
{
  "status": 200,
  "message": "Employees",
  "data": {
    "items": [ { "...": "Employee object" } ],
    "meta": { "page": 1, "limit": 10, "total": 23, "total_pages": 3 }
  }
}
```

### Errors

| Status | `message` | When |
|--------|-----------|------|
| `400` | `Validation failed`, e.g. `data.errors: ["limit must not be greater than 100"]` | Invalid query (`page must be a whole number`, `status must be one of: ACTIVE, INACTIVE`, `department_id must be a valid id`) |
| `403` | `You do not have permission to do this.` | Caller is not ADMIN |

## `GET /employees/me`

**Any logged-in user**, including one who still has to change their password. Returns the caller's own [Employee object](#employee-object), from the token's `employee_id`.

```json
{ "status": 200, "message": "My profile", "data": { "...": "Employee object" } }
```

## `POST /employees`

**ADMIN.** Creates the employee and their login in one step. The system sets the employee code, a random **temporary password**, `status: ACTIVE` and `must_change_password: true`.

### Request

```json
{
  "full_name": "Budi Santoso",
  "email": "budi@dexa.local",
  "phone": "+62 812-3456-7890",
  "position": "Developer",
  "department_id": "d0000000-0000-4000-8000-000000000002",
  "hire_date": "2026-11-10",
  "role": "EMPLOYEE"
}
```

| Field | Required | Rules |
|-------|----------|-------|
| `full_name` | yes | 1–150 characters (trimmed) |
| `email` | yes | Valid email, max 255. Stored lowercase and trimmed. Must not belong to another live employee or login |
| `phone` | no | 6–20 characters: digits, spaces, `-`, optional leading `+`. `""` or `null` means none |
| `position` | yes | 1–100 characters |
| `department_id` | yes | UUID of an existing department |
| `hire_date` | yes | `YYYY-MM-DD`, a real date (`2026-02-30` is rejected) |
| `role` | no | `EMPLOYEE` (default) or `ADMIN`. An HR admin may create another HR admin |

`employee_code`, `status`, `password` and any other field are rejected (`property employee_code should not exist`).

### Response `201 Created`

```json
{
  "status": 201,
  "message": "Employee created",
  "data": {
    "employee": { "...": "Employee object, account.must_change_password = true" },
    "temporary_password": "q7KmT3xPa9WdRf"
  }
}
```

`temporary_password` is shown **only in this response**: it is stored as a bcrypt hash and can't be retrieved later. HR hands it to the employee, who must set their own password at first login (see [Auth API → First login](auth.md#first-login-with-a-generated-password)). Lost it? Use [reset-password](#post-employeesidreset-password).

Temporary passwords are 14 random characters (cryptographically secure), always with an upper-case letter, a lower-case letter and a digit, and no look-alike characters (`0 O 1 l I`).

### Errors

| Status | `message` | When |
|--------|-----------|------|
| `400` | `Validation failed` + `data.errors` | Invalid body, e.g. `full_name is required`, `email must be a valid email address`, `hire_date must be a valid date`, `role must be one of: ADMIN, EMPLOYEE` |
| `400` | `department_id does not match any department` | Unknown department |
| `409` | `This email is already used by another employee` | Email taken by a live employee |
| `409` | `This email is already used by another login` | Email taken by a login (the new employee is undone automatically) |

## `PATCH /employees/:id`

**ADMIN.** Send only the fields that change; at least one is required.

### Request

| Field | Rules | Effect |
|-------|-------|--------|
| `full_name`, `position` | as in create | |
| `email` | as in create | Updates the employee **and** the login email (they stay equal) |
| `phone` | as in create; `null` or `""` clears it | |
| `department_id`, `hire_date` | as in create | |
| `status` | `ACTIVE` or `INACTIVE` | `INACTIVE` blocks the login (resignation). `ACTIVE` on an inactive employee **reactivates** them with a **new temporary password** (rehire) |
| `role` | `ADMIN` or `EMPLOYEE` | Promote / demote, within the [guardrails](#role-guardrails) |

Examples:

```json
{ "position": "Senior Developer", "email": "budi.s@dexa.local" }
```
```json
{ "status": "INACTIVE" }
```
```json
{ "status": "ACTIVE", "hire_date": "2027-03-01" }
```
```json
{ "role": "ADMIN" }
```

### Response `200 OK`

```json
{
  "status": 200,
  "message": "Employee updated",
  "data": {
    "employee": { "...": "Employee object" },
    "temporary_password": null
  }
}
```

`temporary_password` is a string only when this update **reactivated** the employee; show it to HR once, as on create.

### Errors

| Status | `message` | When |
|--------|-----------|------|
| `400` | `Nothing to update: send at least one field` | Empty body |
| `400` | `Validation failed` + `data.errors` | Invalid field |
| `400` | `department_id does not match any department` | Unknown department |
| `403` | `You cannot change your own role or deactivate your own account` | Guardrail: own `role` or `status` |
| `404` | `Employee not found` | Unknown or deleted id |
| `409` | `This email is already used by another employee` / `…by another login` | Email taken |
| `409` | `This is the last active HR admin. Make someone else HR admin first.` | Guardrail: demoting or deactivating the last active ADMIN |

If the login update is refused (e.g. a guardrail), the employee changes from the same request are **undone**: nothing is half-applied.

---

## `POST /employees/:id/reset-password`

**ADMIN.** For an employee who forgot their password. Replaces it with a new temporary password and sets `must_change_password: true`. No body.

```json
{ "status": 200, "message": "Password reset", "data": { "temporary_password": "Nw7pQ2xKmT9aRd" } }
```

| Status | `message` | When |
|--------|-----------|------|
| `403` | `Use "Change password" for your own account` | Resetting your own password |
| `404` | `Employee not found` / `This employee has no login account` | |
| `409` | `This account is deactivated. Reactivate the employee instead.` | Employee is `INACTIVE` (reactivating gives a new password anyway) |

---

## `DELETE /employees/:id`

**ADMIN.** For records created **by mistake** only. Resignations use `PATCH { "status": "INACTIVE" }`, which keeps the person visible and restorable.

Soft-deletes the login **first** (access ends immediately), then the employee. Nothing is removed from the database: the rows get `deleted_at`, disappear from every list and lookup, and their attendance history is kept. The email can be used again for a new employee; the employee code is never reused.

```json
{ "status": 200, "message": "Employee deleted" }
```

| Status | `message` | When |
|--------|-----------|------|
| `403` | `You cannot delete your own account` | Deleting yourself |
| `404` | `Employee not found` | Unknown or already deleted |
| `409` | `This is the last active HR admin. Make someone else HR admin first.` | Deleting the last active ADMIN |

---

## Role guardrails

Apply to `PATCH` (`role`, `status`), reset-password and `DELETE`:

| Rule | Error |
|------|-------|
| Only ADMIN can call these endpoints, so only ADMIN can grant ADMIN | `403 You do not have permission to do this.` |
| Nobody changes their own role or status, resets or deletes themselves | `403` (messages above) |
| The **last active ADMIN** can't be demoted, deactivated or deleted | `409 This is the last active HR admin. Make someone else HR admin first.` |
| Every change records who made it | `updated_by` |

The last-admin rule is safe under concurrency: if two HR admins demote each other at the same moment, exactly one succeeds and the other gets `409` (tested). The change applies at the demoted admin's next request: the gateway checks the current role on every request, so HR endpoints give them `403` right away.

## Lifecycle

| Event | Request | Employee | Login |
|-------|---------|----------|-------|
| New hire | `POST /employees` | created, `ACTIVE` | created, temporary password |
| Forgot password | `POST /employees/:id/reset-password` | — | new temporary password |
| Promotion to HR | `PATCH { "role": "ADMIN" }` | `updated_by` set | `role: ADMIN` |
| Resignation | `PATCH { "status": "INACTIVE" }` | `INACTIVE`, still listed | blocked (`is_active: false`) |
| Rehire | `PATCH { "status": "ACTIVE", "hire_date": "…" }` | `ACTIVE`, same code and history | active, **new** temporary password |
| Created by mistake | `DELETE /employees/:id` | hidden (soft delete) | hidden (soft delete), first |

## TypeScript types (for the frontend)

```ts
export type Role = 'ADMIN' | 'EMPLOYEE'
export type EmployeeStatus = 'ACTIVE' | 'INACTIVE'

export interface Department {
  id: string
  name: string
}

export interface EmployeeAccount {
  user_id: string
  employee_id: string
  email: string
  role: Role
  is_active: boolean
  must_change_password: boolean
  last_login_at: string | null
}

export interface Employee {
  id: string
  employee_code: string
  full_name: string
  email: string
  phone: string | null
  position: string
  department: Department
  hire_date: string
  status: EmployeeStatus
  created_by: string | null
  updated_by: string | null
  created_at: string
  updated_at: string
  account: EmployeeAccount | null
}

export interface EmployeeList {
  items: Employee[]
  meta: { page: number; limit: number; total: number; total_pages: number }
}

export interface ListEmployeesQuery {
  page?: number
  limit?: number
  search?: string
  department_id?: string
  status?: EmployeeStatus
}

export interface CreateEmployeeRequest {
  full_name: string
  email: string
  phone?: string | null
  position: string
  department_id: string
  hire_date: string
  role?: Role
}

export type UpdateEmployeeRequest = Partial<CreateEmployeeRequest> & { status?: EmployeeStatus }

export interface CreatedEmployee {
  employee: Employee
  temporary_password: string
}

export interface UpdatedEmployee {
  employee: Employee
  temporary_password: string | null
}

export interface TemporaryPassword {
  temporary_password: string
}
```
